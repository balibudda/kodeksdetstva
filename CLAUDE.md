# Кодекс детства — памятка для Claude Code

Справочник для родителей и подростков о правах ребёнка, безопасности и законе.
`kodeksdetstva.ru`. Нулевые зависимости в сборке (только один прод-пакет —
`@maxhub/max-bot-api`, для MAX-бота). Живой статус проекта, что сделано и что
в планах — **`STATUS.md`**, читать его первым. Этот файл — про «как тут всё
устроено технически», не про статус.

## Как собрать и посмотреть

```
npm run build   # генерирует dist/ (иконки, OG-картинка, весь сайт)
npm run dev     # build + локальный сервер (scripts/serve.mjs)
```

Деплой — автоматический на каждый `git push` в `main` (Vercel: `buildCommand`
= `node scripts/build.mjs`, `outputDirectory` = `dist`). Ничего руками
публиковать не нужно.

## Модель контента

Одна тема — одна HTML-страница по адресу `/<раздел>/<тема>/`. Данные — обычные
JS-объекты, без CMS и без базы:

- `content/sections.mjs` — 15 разделов (id, slug, title, icon, accent, order,
  lead, frame). `order` определяет порядок на главной, «от острого к базовому» —
  кроме `radost-detstva` («Счастливое детство»), её намеренно поставили вторым
  номером (сразу после «Психики»), чтобы сайт не читался стеной тьмы с первого
  экрана; экстренный доступ всё равно идёт через кнопку 🆘, а не порядок чипов.
- `content/topics/*.mjs` — темы, по одному файлу на раздел (не один в один —
  например `semya.mjs` и `semeynye-dela.mjs` оба существуют, см. ниже почему).
  Схема поля `Topic` описана JSDoc-комментарием в начале `lichnost.mjs` —
  свежую версию смотреть там, не тут (чтобы не разъезжалось).
- `content/contacts.mjs` — федеральные контакты (id, tel/email/url, kind).
- `content/regions.mjs` — региональные контакты (17 регионов, millionniki).
- `content/index.mjs` — точка сборки: импортирует все `TOPICS_*`, склеивает
  в один `TOPICS`, даёт `topicUrl()`, `sectionUrl()`, `validateContent()`.

**Новый файл с темами всегда нужно явно подключить** в `content/index.mjs`
(import + добавить в spread внутри `TOPICS`) — забытый импорт даёт тихий баг:
файл существует, но темы нигде не рендерятся и нет ошибки сборки.

## Правила при добавлении/правке тем

- Раздел выбирайте по смыслу заголовка секции, не «куда влезет». Один раз уже
  проехали: полгода складывали в `semya` («Насилие в семье») темы вроде
  маткапитала и документов — потом пришлось расковыривать на `semya` +
  `semeynye-dela`. Если тема пограничная — лучше на секунду перечитать
  `lead`/`frame` раздела, чем потом резать.
- `related: [...]` — только реальные slug'и. Дублирующиеся slug'и, битые
  `related`, неизвестные `contacts` — всё это ловит `validateContent()` в
  `content/index.mjs`, но только если её вызвать; `scripts/build.mjs` вызывает
  её сам при сборке, так что просто следите, что `npm run build` не ругается.
- `lawQuotes` — только дословные цитаты, сверенные с официальным текстом
  (consultant.ru, garant.ru, sudact.ru, само ведомство). Не пересказ по памяти.
- Кодировка: после каждой пачки правок —
  `grep -nP '[A-Za-z][А-Яа-яЁё]|[А-Яа-яЁё][A-Za-z]' content/topics/<файл>.mjs`
  ловит случайные латинские буквы внутри русских слов (частая опечатка).
- Переносите тему в другой раздел — переносите и старый URL в `redirects`
  блоке `vercel.json` (301, **с обоими вариантами**, со слэшем на конце и без:
  Vercel матчит `source` буквально, trailing slash не нормализует сам).

## Технические грабли, в которые уже наступали

- **Service worker кэш** (`assets/sw.js`): matching всегда через
  `caches.open(CACHE).then(c => c.match(...))` (см. `matchCurrent()`), не
  голый `caches.match(...)` — тот ищет по всем версиям кэша сайта и может
  отдать данные прошлого деплоя. `/regions.json` и `/search-index.json` —
  network-first (данные, не статика), остальная статика — cache-first.
- **MAX Bot API** (`api/max.js`): серверы MAX используют цепочку сертификатов
  «Минцифры России» (Russian Trusted Root/Sub CA), которой нет в обычном
  системном доверии — ни на машине разработчика, ни у Vercel. Поэтому в
  `api/max.js` свой `fetch`-враппер на `node:https` с явным списком CA
  (см. константы в начале файла), передан в SDK через `clientOptions.fetch`.
  Без этого `fetch failed` на любой исходящий запрос к `platform-api2.max.ru`.
  Кнопки в сообщениях — `Keyboard.button.link`, не `openApp`: последний требует
  отдельной регистрации ссылки мини-приложения в кабинете MAX для партнёров
  («Link not found» иначе). MAX сам открывает внешние ссылки во встроенном
  окне (не в браузере) — визуально эффект тот же, что и от `openApp`, так что
  Ник закрыл эту доработку как ненужную (11.09.2026): не переключать обратно,
  пока сам не попросит.
- **Vercel env vars**: добавлять через `vercel env add <NAME> production
  --value "..."` — если пайпить в stdin, может тихо сохранить пустое значение.
  После добавления/смены переменной нужен новый деплой (`vercel --prod --yes`
  или просто `git push`) — на лету функция их не подхватывает.

## Раздел «Новости» (`/novosti/`)

Данные — `content/news.mjs` (массив `NEWS`, схема в JSDoc там же). **Только
законодательство/госинициативы о детях, никакой криминальной хроники** —
осознанное решение Ника, чтобы не свести на нет баланс из «Счастливого
детства». Каждая новость — на своей странице `/novosti/<slug>/` (slug —
`item.slug`, если бот его задал, иначе авто из даты+заголовка через
`slugify()`/`newsItemUrl()` в `build.mjs`). На списке `/novosti/` — короткий
тизер (`newsTeaser()`, ~половина текста, обрезка по границе слова), полный
`summary` — только на отдельной странице. Источник — `rel="nofollow"`
(цитирование факта, не реклама источника). RSS — `/novosti/rss.xml`
(`buildNewsRss()`), автообнаружение через `<link rel="alternate">` в `<head>`.

**Автонаполнение**: `.github/workflows/daily-news-check.yml` (ежедневно +
`workflow_dispatch` вручную) вызывает `anthropics/claude-code-action@v1` по
подписке Ника (`CLAUDE_CODE_OAUTH_TOKEN`, не платный API — сгенерирован
`claude setup-token`, лежит и в GitHub Secrets, и в `~/Desktop/sync.py`).
Требует **и** секрет, **и** установленное GitHub-приложение Claude
(github.com/apps/claude) на репозиторий — без него падает с «Claude Code is
not installed». Полный промпт агента — `instructions/news-check-prompt.md`:
жёсткие правила — без проверяемого `sourceUrl` не публиковать вообще, пустой
день — норм (без пустых коммитов), максимум 3 пункта за прогон, `summary`
писать своими словами (не копировать источник). Проверено вживую 11.09.2026 —
корректно не стал коммитить, когда не нашёл настоящей новости.

**Подписка на email — сознательно НЕ делаем** (обсуждали с Ником 11.09.2026).
Причины: разделу один день, нет истории спроса; сбор почты — это реальные
персональные данные, требует серьёзной переработки `/politika/`, двойного
opt-in, отписки, нового провайдера (Resend, уже есть у Ника для других
проектов, но не подключён к этому домену) — то есть на порядок больше работы
и юридической поверхности, чем стоит того при одном тестовом пункте новостей.
RSS уже закрывает эту потребность для той же аудитории. Возвращаться к идее —
только если через несколько недель будет понятен реальный трафик/спрос.

## Security-хардненинг (11.09.2026)

- `api/tg.js`/`api/max.js`: проверка вебхук-секрета — **fail closed**
  (`if (!SECRET || header !== SECRET)`), не `if (SECRET && ...)`. Раньше при
  отсутствующей переменной окружения проверка молча пропускала все запросы
  вместо того, чтобы их блокировать.
- `vercel.json`: базовые заголовки на все страницы — `X-Content-Type-Options:
  nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`.
- Нет БД и нет форм, пишущих на сервер — «подправить данные на сайте» в
  классическом смысле неоткуда; главная реальная угроза — компрометация
  аккаунтов GitHub/Vercel, у обоих 2FA включена (проверено вручную у Ника).
- Секретов в git-истории не было и нет (сверено `git log --all -p` по
  известным токенам) — секреты только через `process.env`, не хардкодятся.

## Прочие живые файлы

- `.github/workflows/monthly-content-audit.yml` + `scripts/content-audit.mjs` —
  раз в месяц (3 числа) бесплатно проверяет даты `updated` старше 6 месяцев и
  живость ссылок на источники в `contacts`/`regions`, открывает GitHub Issue.
  Ничего не правит сам. Реальные HTTP-ошибки (404/500) и сетевые сбои/403/
  таймауты в отчёте **разделены** — вторые не доказательство мёртвой ссылки
  (многие `.gov.ru` блокируют ботов/не-российские IP), только повод проверить
  руками.
- `api/tg.js`, `api/max.js` — вебхуки ботов Telegram и MAX (зеркалят логику:
  приветствие, поиск по `/search-index.json`, deep-link на тему).
- Токены и секреты (Telegram, MAX, Vercel, GitHub и т. д.) — в
  `~/Desktop/sync.py` на машине Ника. Читать оттуда можно, светить в чате
  или коммитить — нет.

## Vercel deployment cleanup (2026-09-11)

`.github/workflows/vercel-deployment-cleanup.yml` — daily cron, `vercel
remove kodeksdetstva --safe --yes`. Added account-wide after an
account-level "Exceeded free resources" scare traced mostly to
nikolablajen-app's 466 retained deployments, but this project had 69
too (small builds, just high commit volume during active dev). `--safe`
only deletes deployments with no active alias — the live site is never
touched. Full story/root-cause writeup lives in nikolablajen-app's own
CLAUDE.md (search "Vercel Deployment Storage crisis") since that's where
it was diagnosed — not duplicated here.

## Стиль

Тон карточек — прямой, без канцелярита и без давления. Ребёнок — личность, а
не собственность родителя; это не лозунг для одного раздела, а рамка для всего
контента. Подробности стиля/тона — `CONCEPT.md` (местами устарел с момента
ребрендинга «Дитя Бога» → «Кодекс детства», проверяйте факты по `STATUS.md`,
не по `CONCEPT.md`).
