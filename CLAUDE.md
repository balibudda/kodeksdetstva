# Кодекс детства — памятка для Claude Code

Справочник для родителей и подростков о правах ребёнка, безопасности и законе.
`kodeksdetstva.ru`. Нулевые зависимости в сборке **самого сайта**
(`node scripts/build.mjs`) — прод-код только `@maxhub/max-bot-api` (для
MAX-бота). У Android-приложения (Capacitor) — свои devDependencies в
`package.json` (`@capacitor/*`), это отдельная, необязательная для сайта
цепочка сборки, не нарушает нулевую зависимость самого сайта. Живой статус
проекта, что сделано и что в планах — **`STATUS.md`**, читать его первым.
Этот файл — про «как тут всё устроено технически», не про статус.

**Репозиторий публичный с 15.09.2026** (сделан открытым, чтобы Actions
были бесплатными — приватные репо на аккаунте `balibudda` упёрлись в
месячный лимит минут; полная история переписки/обсуждений при этом
сжата в один коммит и перезалита force-push'ем, публично не видна).
**Из-за этого — важное правило на будущее: ничего чувствительного
(реальные значения секретов, личные/деловые детали, пути к файлам с
ключами на компьютере Ника и т.п.) в этот CLAUDE.md/любой другой файл
репозитория не писать** — секреты только через `process.env`/GitHub
Secrets, обсуждение личного/делового — в чате, не в коммитах. `.jks`
keystore и его пароль как и раньше живут вне git, это не изменилось.

## Android-приложение (Capacitor) — для RuStore

`npx cap add android` создал `android/` — обёртка сайта (`webDir: dist`)
в нативный WebView, appId `ru.kodeksdetstva.app`. Не браузерная закладка —
своя иконка, офлайн полностью (тот же service worker).

**Локальный тулчейн** (на машине Ника, 11.09.2026): Android SDK не через
Android Studio, а headless — `brew install --cask android-commandlinetools`
(`ANDROID_HOME=/opt/homebrew/share/android-commandlinetools`), пакеты
`platform-tools`, `platforms;android-35`, `build-tools;35.0.0` через
`sdkmanager`. **JDK — строго 21**, не 17 и не 8 (`brew install --cask
temurin` или `brew install openjdk@21` — на машине уже был; `JAVA_HOME=
/opt/homebrew/opt/openjdk@21`, иначе `./gradlew assembleRelease` падает
с «invalid source release: 21»). `android/local.properties` (не в git) —
`sdk.dir=$ANDROID_HOME`.

**Иконка/сплэш**: `resources/icon.png` (1024, полная, с фоном),
`resources/icon-foreground.png` (1024, safe-zone ~33% для adaptive icon),
`resources/icon-background.png` (сплошной `#3a6b5f`), `resources/splash.png`
(2732, сплошной фон) — нарисованы тем же самописным PNG-кодеком, что и
`scripts/gen-icons.mjs` для иконок сайта (см. `/tmp` при генерации — сам
скрипт не сохранён в репо, только результат; при желании пересоздать
логику смотреть `scripts/gen-icons.mjs` как образец). Генерация всех
плотностей — `npx capacitor-assets generate --android --iconBackgroundColor
'#3a6b5f' ...`. **Важно**: инструмент читает `resources/`, но при
однократном запуске у некоторых версий срабатывает только если файлы
лежат прямо в `assets/` (корень) — если разово копируете их туда для
генерации, не забудьте убрать после (`assets/` иначе целиком копируется
в `dist/assets/` при сборке сайта — мёртвый вес на каждой странице).

**Подпись релиза**: `android/keystore.properties` (в `.gitignore`,
формат `storeFile=`/`storePassword=`/`keyAlias=`/`keyPassword=`), сам
`.jks`-файл — **вне репозитория и вне git полностью** (Ник знает, где
он лежит). **Это самый критичный файл во всей этой цепочке — потеря =
невозможность когда-либо обновить приложение в RuStore под тем же
appId.** Бэкапить отдельно от git.
`android/app/build.gradle` читает `keystore.properties` и подписывает
`release`-сборку, если файл существует (иначе собирается неподписанным).

**14.09.2026 — путь с кириллицей ломал сборку, пофиксили сам Gradle-код,
не переезд**: Ник переместил `.jks`-файлы в новую папку с кириллицей в
пути. Реальная причина ошибки «Keystore file not
found» — не сам перенос, а `Properties.load(new FileInputStream(...))`
в `build.gradle`: дефолтная кодировка ISO-8859-1 ломала кириллицу в
пути. Исправлено на уровне кода — `build.gradle` теперь читает файл
явно как UTF-8 (`keystorePropertiesFile.withReader('UTF-8') { reader ->
keystoreProperties.load(reader) }`). После фикса путь с кириллицей
работает нормально, `./gradlew --rerun-tasks assembleRelease` проходит.
Полная история — CLAUDE.md проекта kodeksdeneg (искать «путь с
кириллицей ломал сборку»).

**Публикация файла APK**: GitHub Releases на **приватном** репозитории
не отдаёт ассеты анонимным посетителям без токена (проверено — 404).
Поэтому файлы релиза лежат в отдельном **публичном** репозитории
`balibudda/kodeksdetstva-releases` (только APK, без исходного кода).
Кнопка «Скачать APK» в подвале сайта ссылается на
`.../releases/latest/download/kodeksdetstva.apk` — при новом релизе
называть ассет всегда одинаково (`kodeksdetstva.apk`), тогда ссылка не
меняется. Сборка + релиз вручную:
```
node scripts/build.mjs && npx cap sync android
cd android && JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew assembleRelease
gh release create vX.Y.Z app/build/outputs/apk/release/app-release.apk \
  --repo balibudda/kodeksdetstva-releases --title "..." --notes "..."
  # переименовать ассет в kodeksdetstva.apk при загрузке, если gh не подхватил имя сам
```
Перед каждым релизом поднять `versionCode`/`versionName` в
`android/app/build.gradle` **и** синхронно обновить `public/app-version.json`
(versionCode/versionName/releaseDate/downloadUrl) — из него приложение
(`@capacitor/app`, см. ниже) узнаёт, что вышло обновление. Забыли обновить
файл — бейдж «Доступно обновление» просто не появится у тех, кто уже
установил приложение, никакой ошибки не будет.

**Бейдж версии и проверка обновлений** (в подвале каждой страницы, видно
сразу, без открытия меню; только внутри приложения —
`window.Capacitor.isNativePlatform()`): `@capacitor/app` → `App.getInfo()`
даёт версию из самого APK (`build` = versionCode, `version` = versionName),
дальше `nav.js` сверяет с `/app-version.json` на живом сайте (он не
«замороженный» как контент внутри APK — тянется каждый раз заново). Если
на сайте `versionCode` больше — показывает ссылку на скачивание. Офлайн —
тихо ничего не показывает, не ошибка.

**КРИТИЧНО — навигация внутри приложения и `html5mode`** (11.09.2026,
нашли и чинили дважды за одну сессию, второй раз — правильно). Локальный
сервер Capacitor (`WebViewLocalServer.java`, смотрели исходники в
`node_modules/@capacitor/android/`) умеет отдавать РОВНО ДВА типа путей:
`/` и путь, где `html5mode=true` (тогда любой путь без точки отдаёт
корневой `index.html` — режим для SPA, всё остальное отдаёт **null**, и
WebView делает настоящий сетевой запрос к `https://localhost/...`, а там
никто не слушает → `net::ERR_CONNECTION_REFUSED`).
- Первая попытка фикса (v1.2, неверная): выключить `server.html5mode` в
  `capacitor.config.json` — казалось логичным (у нас не SPA), но открыла
  ВТОРОЙ баг — вместо неправильного контента (главная вместо нужной
  страницы) все ссылки стали давать `ERR_CONNECTION_REFUSED` совсем,
  потому что без html5mode для extensionless-путей у сервера нет
  обработчика вообще.
- Правильный фикс (v1.3): `html5mode` можно оставить как есть, реальное
  решение — в `nav.js`, только при `isNativePlatform()`: перехватываем
  клики по внутренним ссылкам (`href` начинается с `/`, без расширения,
  не `_blank`/`mailto`/`tel`) и дозаписываем `index.html` на конец —
  единственный путь, который сервер гарантированно отдаёт правильно
  (у него ветка «есть точка в пути → отдать файл»). Заодно отключили
  регистрацию service worker внутри приложения — там он не нужен (контент
  уже локально в APK), а его собственные precache-fetch по тем же
  extensionless путям попадали в ту же дыру.
- **Урок на будущее**: multi-page статический сайт (не SPA) в Capacitor —
  не «из коробки» сценарий, тестировать реальную навигацию (не только
  главную!) на устройстве/эмуляторе перед каждым релизом, не полагаться
  на то, что раз собралось — значит работает.

**RuStore**: физлицо может публиковать приложение **без ИП** — нужна
только верификация через VK ID (паспорт + лицо в камеру). ИП/юрлицо
требуется только для монетизации через платёжные инструменты RuStore —
у нас приложение бесплатное, это не блокер (в отличие от nikolablajen-app,
где именно монетизация и была причиной). RuStore принимает и APK, и AAB;
первый релиз обычно достаточно как APK. Требования, которым наша сборка
уже соответствует: `targetSdkVersion` ≥ 28 (у нас 36), подпись ключом
RSA ≥ 2048 бит (у нас 2048). Сама подача в RuStore Console — ручное
действие Ника, не автоматизируется отсюда.

## Модель контента

Одна тема — одна HTML-страница по адресу `/<раздел>/<тема>/`. Данные — обычные
JS-объекты, без CMS и без базы:

- `content/sections.mjs` — 15 разделов (id, slug, title, icon, accent, order,
  lead, frame). `order` определяет порядок на главной, «от острого к базовому» —
  кроме `radost-detstva` («Счастливое детство»), её намеренно поставили вторым
  номером (сразу после «Психики»), чтобы сайт не читался стеной тьмы с первого
  экрана; экстренный доступ всё равно идёт через кнопку 🆘, а не порядок чипов.
- `content/topics/*.mjs` — темы, по одному файлу на раздел (не один в один —
  например `semya.mjs` и `semeynye-dela.mjs` оба существуют, см. ниже почему).
  Схема поля `Topic` описана JSDoc-комментарием в начале `lichnost.mjs` —
  свежую версию смотреть там, не тут (чтобы не разъезжалось).
- `content/contacts.mjs` — федеральные контакты (id, tel/email/url, kind).
- `content/regions.mjs` — региональные контакты, **83 из 89 субъектов РФ**
  (все, кроме Крыма, Севастополя и 4 регионов 2022 года — сознательно, см.
  STATUS.md). У каждого своя страница `/regiony/<slug>/` (`regionUrl()` в
  `content/index.mjs`, `slug` — явное поле, не транслитерация на лету).
  `/regiony/` — индекс со своим поиском по подстроке (`#region-filter` в
  `nav.js`, без индекса, список пока небольшой). Полезный трюк на будущее
  (для оставшихся 6 регионов, если/когда решите их добавить): страница
  уполномоченного на федеральном портале — `deti.gov.ru/upr<NN>`, где
  `NN` почти всегда совпадает с автомобильным кодом региона (подтверждено
  эмпирически на 59 из 61 добавленного региона; Адыгея и ЯНАО — исключения,
  см. `verify: true` в их записях).
- `content/index.mjs` — точка сборки: импортирует все `TOPICS_*`, склеивает
  в один `TOPICS`, даёт `topicUrl()`, `sectionUrl()`, `regionUrl()`,
  `validateContent()` (проверяет и дубли slug/id регионов тоже).

**Новый файл с темами всегда нужно явно подключить** в `content/index.mjs`
(import + добавить в spread внутри `TOPICS`) — забытый импорт даёт тихий баг:
файл существует, но темы нигде не рендерятся и нет ошибки сборки.

**Порядок тем внутри раздела = порядок объектов в файле.** `topicsOfSection()`
в `content/index.mjs` — обычный `filter()`, без `sort()`: что первое в массиве
`TOPICS_<РАЗДЕЛ>`, то первая карточка на странице раздела. Это осознанно
используется: например в `razvod.mjs` тема `razvod-bez-travmy-rebenka`
(позитивная, «развод не обязан травмировать ребёнка») стоит первой в файле —
специально, чтобы человек, открывший раздел про войны за ребёнка и похищения,
не упирался сразу в самое тяжёлое. Добавляя тему в уже тяжёлый раздел —
подумайте, нужно ли её тоже поставить не в конец.

**Иконки разделов — SVG, не эмодзи.** `content/icons.mjs` (`SECTION_ICONS` по
`section.id`, не по `slug` — они не всегда совпадают, см. `sryv` = «Подросток
и закон»; проверять через `SECTIONS.map(s => s.id)`, не угадывать по
заголовку). `sectionIconSvg(id, size)` — `currentColor`, наследует цвет
раздела через CSS (`var(--sec)` на обёртке). Новый раздел — сразу добавить
иконку сюда, иначе `sectionIconSvg()` тихо вернёт `''` (пустая иконка, не
ошибка сборки — эта дыра не ловится `validateContent()`).

**Пиктограммы тем — отдельно, `content/topic-icons.mjs`** (11.09.2026).
Не 162 уникальные иконки — компактная палитра `TOPIC_ICONS` (29 значков:
15 переиспользованы прямо из `SECTION_ICONS`, 14 новых — money/warning/
book/music/paw/tree/globe/road/medical/moon/eye/clock/target/flag), и
`TOPIC_ICON_MAP` — `slug` темы → ключ иконки, по одной записи на каждую
из 162 тем. `topicIconSvg(slug, size)` — как `sectionIconSvg()`, но по
теме. Используется в 4 местах: карточки на страницах разделов
(`renderSection`), короткий список на главной (`sec-topics`), `/vse-temy/`,
обе группы на `/tebe/`. **Новая тема — сразу добавить строку в
`TOPIC_ICON_MAP`**, иначе `topicIconSvg()` вернёт `''` молча (та же дыра,
что и с `sectionIconSvg()` — не ловится `validateContent()`); при
добавлении смотрите на уже похожие темы в том же разделе, чтобы не
плодить новый ключ иконки без необходимости — вся идея в переиспользуемой
палитре, не в бесконечном росте уникальных значков.

**Шрифт — Golos Text, самохостинг**, не Google Fonts CDN (`assets/fonts/*.woff2`
+ `@font-face` в `styles.css`, в PRECACHE service worker'а). Меняете шрифт —
не забудьте обновить оба места и лицензионный файл `assets/fonts/OFL-LICENSE.txt`.

**Внутренние ссылки `[[slug]]` / `[[slug|подпись]]`** — парсит `richText()` в
`scripts/build.mjs`, применяется вместо `esc()` в `block()` (first/law/steps/
say/dont) и в `sut`/`redFlags`. Если slug не существует в `TOPICS_BY_SLUG` —
сборка падает с понятной ошибкой, а не тихо оставляет мёртвый текст. Пишите
`[[slug|человеческая подпись]]` там, где раньше был бы «см. отдельно тему X» —
именно так поймал и полностью убрал ~45 мёртвых кросс-ссылок 11.09.2026.

## Правила при добавлении/правке тем

- Раздел выбирайте по смыслу заголовка секции, не «куда влезет». Один раз уже
  проехали: полгода складывали в `semya` («Насилие в семье») темы вроде
  маткапитала и документов — потом пришлось расковыривать на `semya` +
  `semeynye-dela`. Если тема пограничная — лучше на секунду перечитать
  `lead`/`frame` раздела, чем потом резать.
- `related: [...]` — только реальные slug'и. Дублирующиеся slug'и, битые
  `related`, неизвестные `contacts` — всё это ловит `validateContent()` в
  `content/index.mjs`, но только если её вызвать; `scripts/build.mjs` вызывает
  её сам при сборке, так что просто следите, что `npm run build` не ругается.
- `lawQuotes` — только дословные цитаты, сверенные с официальным текстом
  (consultant.ru, garant.ru, sudact.ru, само ведомство). Не пересказ по памяти.
- Кодировка: после каждой пачки правок —
  `grep -nP '[A-Za-z][А-Яа-яЁё]|[А-Яа-яЁё][A-Za-z]' content/topics/<файл>.mjs`
  ловит случайные латинские буквы внутри русских слов (частая опечатка).
- Переносите тему в другой раздел — переносите и старый URL в `redirects`
  блоке `vercel.json` (301, **с обоими вариантами**, со слэшем на конце и без:
  Vercel матчит `source` буквально, trailing slash не нормализует сам).
- **Точно / неточно — разделяйте явно в тексте темы**, если тема касается
  международных/межстрановых вопросов или вообще чего-то, что меняется по
  стране/ведомству и не проверяется одним источником (см. `alimenty-s-
  roditelya-za-granicey`, `brak-s-inostrancem-rebenok`). Не сглаживайте и не
  давайте один общий «рецепт на все случаи», если его в реальности нет —
  прямо пишите «точно: …» / «неточно, зависит от страны — проверяйте
  отдельно» и куда идти уточнять (МИД/консульство/Минюст/юрист). Ник просил
  это явно (11.09.2026): «где точная информация — напиши, где не точная —
  так и напиши, нет данных точных».

**Размер текста (A-/A+ в шапке)** — один множитель `--fs` (CSS custom
property, дефолт `1`, шаг 0.1, диапазон 0.8–1.4). Все 80+ объявлений
`font-size` в `styles.css` — не голые px, а `calc(Npx * var(--fs, 1))`;
добавляя новый `font-size`, пишите его в этом же виде, иначе конкретный
элемент не будет масштабироваться вместе с остальным текстом. Сами
кнопки A-/A+ (`.fs-ctl`/`.fs-btn`) — фиксированного размера намеренно.
Выбор — `localStorage['kd_font_scale']`, применяется рано в `<head>`
(до отрисовки, чтобы не было «скачка») и обработчиком в `nav.js`.

**`favicon.ico`** — генерируется в `scripts/gen-icons.mjs` (32×32 + 16×16,
PNG-кадры внутри ICO-контейнера, тем же самописным PNG-кодеком, что и
остальные иконки). Раньше отдавал 404 — был только `favicon.svg`; часть
краулеров дёргает `/favicon.ico` напрямую независимо от `<link rel="icon">`.
Меняете лого/фавикон — перегенерировать (`npm run icons`) и закоммитить
`public/favicon.ico`, сборка Vercel (`node scripts/build.mjs` напрямую,
без `npm run build`!) сама его не создаёт, см. следующий пункт.

**Vercel buildCommand = `node scripts/build.mjs`**, не `npm run build`
(они разные! см. `package.json`) — значит `gen-icons.mjs`/`gen-og.mjs`
на деплое **не запускаются**. PNG-иконки, `favicon.ico`, OG-картинка —
все генерятся один раз локально и лежат закоммиченными в `public/`. Если
меняете логотип/цвета/шрифт иконки — обязательно `npm run icons`/`npm run
og` локально и закоммитить результат, иначе на проде останется старое.

**Страница `/vse-temy/`** — сплошной пронумерованный список всех тем (1..N,
без раздела/группировки, только реальные ссылки) — сделали, когда цифра

пустое обещание. Ссылка со счётчика на главной ведёт сюда.

## Технические грабли, в которые уже наступали

- **Service worker кэш** (`assets/sw.js`): matching всегда через
  `caches.open(CACHE).then(c => c.match(...))` (см. `matchCurrent()`), не
  голый `caches.match(...)` — тот ищет по всем версиям кэша сайта и может
  отдать данные прошлого деплоя. `/regions.json` и `/search-index.json` —
  network-first (данные, не статика), остальная статика — cache-first.
- **MAX Bot API** (`api/max.js`): серверы MAX используют цепочку сертификатов
  «Минцифры России» (Russian Trusted Root/Sub CA), которой нет в обычном
  системном доверии — ни на машине разработчика, ни у Vercel. Поэтому в
  `api/max.js` свой `fetch`-враппер на `node:https` с явным списком CA
  (см. константы в начале файла), передан в SDK через `clientOptions.fetch`.
  Без этого `fetch failed` на любой исходящий запрос к `platform-api2.max.ru`.
  Кнопки в сообщениях — `Keyboard.button.link`, не `openApp`: последний требует
  отдельной регистрации ссылки мини-приложения в кабинете MAX для партнёров
  («Link not found» иначе). MAX сам открывает внешние ссылки во встроенном
  окне (не в браузере) — визуально эффект тот же, что и от `openApp`, так что
  Ник закрыл эту доработку как ненужную (11.09.2026): не переключать обратно,
  пока сам не попросит.
- **Vercel env vars**: добавлять через `vercel env add <NAME> production
  --value "..."` — если пайпить в stdin, может тихо сохранить пустое значение.
  После добавления/смены переменной нужен новый деплой (`vercel --prod --yes`
  или просто `git push`) — на лету функция их не подхватывает.
- **`telegram-web-app.js` грузится не на каждой странице для всех, а только
  внутри Telegram** (`scripts/build.mjs`, инлайн-скрипт в `<head>`) — меньше
  внешних доменов для обычных посетителей (11.09.2026, часть разбора
  «сайт грузит в РФ»). Ловушка, в которую чуть не наступили: Telegram кладёт
  метку `tgWebApp*` в `location.hash`/`search` **только на самой первой**
  открытой странице, не переставляет её при обычной навигации по ссылкам — а
  сайт многостраничный, не SPA. Поэтому факт «мы в Telegram» дополнительно
  запоминается в `sessionStorage` при первом обнаружении метки — без этого
  тема/кнопка «назад»/deep-link у `assets/tg.js` ломались бы на второй и
  далее странице внутри Telegram-сессии.

## Security-хардненинг (11.09.2026)

- `api/tg.js`/`api/max.js`: проверка вебхук-секрета — **fail closed**
  (`if (!SECRET || header !== SECRET)`), не `if (SECRET && ...)`. Раньше при
  отсутствующей переменной окружения проверка молча пропускала все запросы
  вместо того, чтобы их блокировать.

  nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`.
- Нет БД и нет форм, пишущих на сервер — «подправить данные на сайте» в
  классическом смысле неоткуда; главная реальная угроза — компрометация
  аккаунтов GitHub/Vercel, у обоих 2FA включена (проверено вручную у Ника).
- Секретов в git-истории не было и нет (сверено `git log --all -p` по
  известным токенам) — секреты только через `process.env`, не хардкодятся.

## УСТАРЕЛО (было верно до 16.09.2026) — Реальный трафик шёл не на Vercel, а через Cloudflare → GitHub Pages зеркало (обнаружено/починено 13.09.2026)

1. **Зеркало было опубликовано один раз и никогда не обновлялось.** Добавлен

2. **У `kodeksdetstva-web` тип сборки GitHub Pages был `workflow`, а не

   build_type=legacy` — исправлено). С `legacy` пуш в `main` сам собирает
   сайт, как и у `kodeksdeneg-web` (тот же паттерн для сайта-брата).

## Меню Telegram Mini App переставало работать после «Обновить» (13.09.2026)

`assets/tg.js` проверял `tg.initData` как признак «мы внутри Telegram» — но
Telegram кладёт метку `tgWebApp*` в адрес только на самой первой открытой
странице и сам же подчищает её оттуда при инициализации своего
`telegram-web-app.js`. После нажатия кнопки «Обновить» (`location.reload()`)
`tg.initData` на этот раз пустое, хотя пользователь всё ещё внутри Telegram —
`tg.js` тихо выходил, не вызывая `tg.ready()`/`tg.expand()`/
`disableVerticalSwipes()` заново, и Telegram возвращал свои жесты
(сворачивание/pull-to-refresh) поверх страницы — меню переставало
реагировать на нажатия. Исправлено: используем тот же `sessionStorage`-флаг
(`kd_tg`), что и `build.mjs` при решении, грузить ли сам `telegram-web-app.js`
— он переживает `reload()`, в отличие от `tg.initData`.

  первый шаг темы, Whisper даёт тайминг слов для синхронных подписей внизу
  на непрозрачной (`black@0.92`) плашке. Текст поста (`buildCaption()`) —
  **весь** контент темы (суть, по возрасту, шаги, закон, что сказать/не
  сказать) + ссылка на сайт, не короткий тизер (правило проекта, как у
  nikolablajen — `feedback_social_post_max_volume`). Локально нужен
  `ffmpeg-full` (не голый Homebrew `ffmpeg` — без `libfreetype`/`drawtext`),
  в CI обычный `apt-get install ffmpeg` уже умеет `drawtext`.
- **`scripts/social/post-youtube.mjs`** — публикация на YouTube (Shorts,
  `privacyStatus: public`, categoryId 27 = Education). Нужны
  `YT_CLIENT_ID`/`YT_CLIENT_SECRET`/`YT_REFRESH_TOKEN` (Desktop OAuth
  client, отдельный Google Cloud проект `kodeks-social` — специально не
  тот же, что у nikolablajen, чтобы не делить квоту YouTube API).
- **`scripts/social/post-facebook.mjs`** + **`scripts/social/
  github-asset-host.mjs`** — публикация на Facebook-страницу «Кодекс
  Детства» через Graph API (видео + полный текст + ссылка). Facebook
  принимает только `file_url`, не сам файл — временный публичный хостинг
  через отдельный репозиторий `balibudda/kodeksdetstva-assets` (один
  «плавающий» Release `social-temp`, файлы удаляются сразу после
  использования). Нужны `FB_PAGE_ID`/`FB_PAGE_TOKEN`/`GH_ASSETS_TOKEN`.
- **`scripts/social/daily-youtube-post.mjs`** — берёт следующие **3** ещё не
  опубликованные темы по порядку `TOPICS` (без повторов —
  `scripts/social/posted-youtube.json`, простой массив slug'ов; `--count=N`
  меняет число, `--slug=<slug>` берёт одну конкретную вместо очереди),
  рендерит и публикует каждую на YouTube, затем (необязательно, если
  секреты заданы) на Facebook — Facebook-шаг не роняет весь прогон, если сам
  упадёт (YouTube уже опубликован к этому моменту). Трекер сохраняется
  **после каждой темы**, не одним разом в конце — если прогон упадёт на
  2-й из 3, 1-я не потеряется.
- **`.github/workflows/daily-youtube-post.yml`** — ежедневный автопилот,
  ~07:30 Bangkok, плюс ручной запуск с конкретным `--slug=`. Коммитит
  обновлённый `posted-youtube.json` обратно в `main`.

**Свой отдельный Google Cloud проект и Meta-приложение на каждый сайт** —
осознанный выбор (как и с YouTube), не смешивать квоты/креды между
kodeksdeneg/kodeksdetstva/nikolablajen.

**Facebook: реальная ловушка при выдаче прав.** В Graph API Explorer права
`pages_manage_posts`/`pages_read_engagement` **не показываются в поиске**,
пока не добавлены вручную на странице приложения → «Сценарии использования»
→ «Управление всем на вашей Странице» → там у каждого права есть кнопка
«Добавить»/«Add» (Standard Access, без App Review — работает сразу для
своих же страниц). Без этого шага можно случайно выбрать в списке
устаревшее `manage_pages` (реального разрешения давно не существует) и
словить `Invalid Scopes` при генерации токена.

**YouTube: канал за пределами Google-аккаунта, к которому логинишься, может
не подхватиться `mine=true`.** Если Google-аккаунт управляет несколькими
YouTube-каналами (свой личный + Brand Account'ы), OAuth-консент может
привязать доступ не к тому каналу, даже после переключения активного
канала в интерфейсе youtube.com/Studio, в свежем инкогнито-окне и даже с
совершенно новым, никогда не использовавшимся OAuth-клиентом — переключение
UI не долетает до окна авторизации, и это не «залипание» конкретного
клиента (проверено при подключении kodeksdeneg — тот же самый Google-
аккаунт стабильно резолвился в @kodeksdetstva, пока не помог `&authuser=1`
в самой ссылке авторизации — см. CLAUDE.md `kodeksdeneg` для полной
истории). Проверять результат всегда через
`channels?part=snippet&mine=true`, не доверять интерфейсу на слово.
**Никогда не отзывать доступ приложению целиком** через
myaccount.google.com/permissions, чтобы «начать заново» — это révoke'ает
разом ВСЕ каналы, которым этот OAuth-клиент когда-либо выдавал токены, не
только проблемный (чуть не снесли рабочий доступ к этому самому каналу,
пытаясь починить доступ к kodeksdeneg).

**Facebook — реальный подключён и опубликован живьём 13.09.2026**: страница
«Кодекс Детства», первые 3 ролика набрали 83/72/29 просмотров в тот же
день. **Telegram-канал + Дзен — следующий шаг**, Ник заведёт сам, пришлёт
доступы, дальше подключаем в тот же `daily-youtube-post.mjs` (тот же
рендер, тот же список тем — просто ещё один шаг публикации после
Facebook).

`post-tiktok.mjs` (идентичная копия в обоих репозиториях) после каждого

(`REPOS` константа) — токен общий на два независимых репозитория,
ротируется при каждом использовании, и без синхронизации тот проект,
что публикует вторым, получил бы уже протухший токен.

**Полная история одной реальной, неочевидной проблемы** (TikTok

сохраняются, но не влияют на реальную проверку; фикс — использовать уже
рабочий `nikolablajen.com/tiktok-auth`, который 301-редиректит на `.ru`)
живёт в CLAUDE.md проекта **kodeksdeneg** (искать «TikTok — общий
аккаунт») — не дублируется здесь. Если снова понадобится
(пере)авторизовать этот аккаунт — читать оттуда.

## Стиль

Тон карточек — прямой, без канцелярита и без давления. Ребёнок — личность, а
не собственность родителя; это не лозунг для одного раздела, а рамка для всего
контента. Подробности стиля/тона — `CONCEPT.md` (местами устарел с момента
ребрендинга «Дитя Бога» → «Кодекс детства», проверяйте факты по `STATUS.md`,
не по `CONCEPT.md`).
